# Analysis Output Files

This file describes how outputs are computed. Retain files in the
repository-local `analyses/` directory only when they satisfy the policy in
`doc/analyses.md`; ordinary notebook-derived summary tables should be
regenerated rather than stored there.

## When to use this file
Use this file when:
- locating generated CSV files in the `analyses` folder
- understanding the row grain and columns of consolidated analysis tables
- deciding which CSV to use for downstream statistics or plotting

Do NOT use this file for:
- locating raw data files (see `file_structure.md`)
- interpreting raw text or `.mat` file contents (see `file_contents.md`)
- understanding experimental run counts and subject-specific exceptions (see `experiment_structure.md`)

## Common Metadata Columns

The consolidated CSVs follow the same basic organization:

- `subject_id`
  - Subject identifier, e.g. `e21`.
- `group`
  - Group assignment from `code/src/posthoc_analysis/config.py`.
  - Values:
    - `experimental` = BCI group
    - `control` = mental-rehearsal control group
- `session_id`
  - Integer session number in experiment order.
  - Values usually range from `1` to `5`.
- `run_id`
  - Sequential non-practice run number within that subject/session after consolidation-specific practice handling.
  - For documented exceptions, see `experiment_structure.md`.

## `all_subjects_training.csv`

### Purpose
Trial-level consolidated training-task data across subjects, Sessions 1 and 5, and non-practice training runs.

### Generated by
`posthoc_analysis.consolidated.generate_consolidated_training_csv()`

### Row grain
One row = one training trial.

### Shape
- One row per available non-practice training trial: normally 720 per participant
  (8 Session-1 runs + 4 Session-5 runs, each with 60 trials). Missing runs are
  reported explicitly; do not hardcode the historical row count.
- The corrected schema retains the original columns and adds RT provenance/QC.

### Columns

- `subject_id`
  - Subject identifier.
- `group`
  - `experimental` or `control`.
- `session_id`
  - Training session number.
  - Training is expected in Sessions `1` and `5`.
- `run_id`
  - Sequential training run number within session after excluding `training_practice`.
  - Session 1 typically has runs `1` to `8`.
  - Session 5 typically has runs `1` to `4`.
- `task_type`
  - Run task label parsed from the run folder name.
  - Expected value for this CSV: `training`.
- `trial`
  - Trial index within run.
  - Expected values: `1` to `60`.
- `task`
  - Trial type from `.analysis.txt`.
  - `1` = distractor
  - `0` = no distractor
- `feedback`
  - Behavioral response outcome.
  - `1` = correct
  - `2` = incorrect
  - `3` = timeout
- `target_position`
  - Target location code from `.analysis.txt`.
  - Expected values: `1`, `2`, `3`, `4`.
- `distractor_position`
  - Distractor location code from `.analysis.txt`.
  - Expected values: `0`, `2`, `4`.
  - `0` indicates no distractor.
- `dot_side`
  - Response side.
  - `1` = right
  - `0` = left
- `intertrial_interval_ms`
  - Intertrial interval in milliseconds.
- `bci_output`
  - BCI output column from `.analysis.txt`.
  - For training runs, expected value is `99`.
- `rt_samples`
  - Actual GDF response sample minus stimulus sample; NaN without exactly one response.
  - Historical CSVs incorrectly stored text milliseconds under this name.
- `rt_ms`
  - Analysis RT consumed by existing cleaning/plots: GDF RT when available;
    aligned text milliseconds for absent GDF responses with text RT <50 ms.
- `gdf_rt_ms`
  - GDF-only sample difference / verified 512 Hz × 1000; stays NaN without a
    unique recorded response, including trials with a text fallback.
- `condition`
  - `no_distractor`, `distractor_right`, or `distractor_left` from Status code.
- `stimulus_trigger`, `stimulus_sample`, `response_sample`
  - GDF stimulus code and sample indices; response sample is NaN unless unique.
- `rt_source`, `sfreq_hz`
  - `rt_source` is `gdf_status` or `trigger_text_fallback`. `sfreq_hz` is the
    GDF sampling rate (512), never a conversion factor for text RT.
- `response_count`, `alignment_error`
  - Number of responses strictly between this stimulus and the next (recording
    end for the last). Multiple responses flag an alignment error and yield NaN RT.
- `text_rt_ms`
  - Text response minus stimulus milliseconds. Used as an explicit fallback
    only for the audited sub-50 ms missing-response pattern.

Regenerate with `generate_consolidated_training_csv()` after the clock fix.
Existing saved tables with the old formula are invalid for RT analyses; rebuild
from raw GDF rather than rescaling cleaned averages. The generator reports
run-level errors and refuses to overwrite the CSV if any collected run fails
GDF reconstruction. `apply_training_text_rt_fallback()` pools the audited
trigger-lockout cases after GDF reconstruction, preserving original sample
fields and marking provenance. Multiple responses, missing files, alignment
failures, and absent responses with text RT ≥50 ms are not filled. All pooled
trials still fail the existing 150 ms minimum, but now contribute to descriptive
<150 ms counts. In sequential exclusions, correct fast trials count under low
RT and incorrect trials remain under non-correct responses without double
counting. The notebook rebuilds data in **Consolidated Trial-wise Data**, then runs the
existing RT/distractor-cost analyses and RT-change figure functions. Its final
**Training RT clock correction audit** section inspects the same rebuilt table
without repeating reconstruction or introducing a second cleaning workflow.

## Distractor-Trial RT Figure

### Purpose
Average training reaction time for distractor trials only, split by group and
Session 1 vs Session 5.

### Generated by
`posthoc_analysis.behavioral.summarize_distractor_trial_reaction_time_from_training_csv()`

### Source
`all_subjects_training.csv`

### Computation
Uses the same RT cleaning convention as the primary training RT analysis:

- training rows only
- correct responses only (`feedback == 1`)
- exclude missing RT and RT `< 150 ms`
- remove RT outliers using subject/session mean ± 3 SD across all retained
  training trials
- compute subject/session mean RT for distractor trials only
- average subject means by group and session, with SEM across subjects

## Color/Shape Planned Correct-Trial RT Pipeline

### Purpose
Final Color/Shape RT cleaning pipeline for downstream RT analyses.

### Generated by
`posthoc_analysis.color_shape.load_clean_and_plot_color_shape_planned_rt_pipeline()`

### Cleaning Order

1. Start from `all_subjects_color_shape_main_task_annotated.csv`.
2. Keep correct response trials only (`chose_best == 1`).
3. Remove correct trials with `rt < 150 ms`.
4. Within each subject/session, compute median RT and MAD from the remaining
   correct trials.
5. Remove trials where `abs(rt - median_rt) > 3 * MAD`.
6. Compute subject/session mean RT from retained trials.

- Starting main-task trials: 19,200
- Incorrect-response trials removed before RT analyses: 1,614
- Correct trials removed for `rt < 150 ms`: 3
- Correct trials removed as 3 MAD RT outliers: 2,206
- Total trials removed across all steps: 3,823
- Trials retained for RT analyses: 15,377

### Design

- between-subject factor: `group` (`bci`, `control`)
- within-subject factor: `session` (`pre`, `post`)
- subject identifier: `subject_id`

### Implementation note
The implementation uses `pingouin.mixed_anova` when `pingouin` is installed.
In the current environment, `pingouin` is not installed, so the saved tables use
the equivalent tests for this 2-group × 2-session design:

- group effect: independent t-test on each subject's pre/post mean
- session effect: participant-weighted marginal change tested against the within-group change residual (N−2 df)
- group × session interaction: independent t-test on post-pre change scores by
  group

Group and interaction use `F = t²`; Session uses the mixed-design within-group change error stratum. All three effects have numerator df 1 and error df N−2.

## Previous BCI feedback and next-trial decoding RT (exploratory)

Implemented in `posthoc_analysis.feedback_rt` and `feedback_rt_stats`; orchestrated
in the final **Exploratory analysis: previous BCI feedback and next-trial RT**
section of `notebooks/posthoc_analysis.ipynb` using Pd_AI. Outputs live in
`analyses/feedback_next_trial_rt/` as explicitly requested (see `analyses.md`).

### Functions and timing/alignment rules

- `load_feedback_rt_input`: canonical/fallback CSV lookup, key/group/value audits.
- `load_decoding_gdf_rt`, `reconstruct_decoding_events`: labeled raw Status
  transitions with MNE's established onset convention, 512 Hz, 60 stimulus
  anchors, and raw transition validation. Responses must occur strictly after
  the stimulus and before the following fixation. The last trial ends at the
  recording boundary. Missing/ambiguous responses or fixation boundaries yield
  NaN; no text-trigger RT or training-task fallback is applied.
- `reconstruct_and_align_feedback_rt`: compare all available behavioral fields
  against same-subject/session raw analysis files to establish unique run
  identity, then verify the entire GDF stimulus condition/side sequence. Missing
  analysis, ambiguous matches, and missing GDF are logged without guessed run
  offsets. Practice-labeled files are omitted. Practice-like files absent from
  consolidated behavioral data cannot enter the analysis. Raw audit records can
  overlap; only `unmatched_consolidated_runs` is the unique lost-run ledger.
- `build_feedback_rt_pairs`: strictly consecutive trials within runs. Use
  `decoding_bci_output` from the previous trial and correctness/type/RT from the
  current trial. Previous-trial correctness is unrestricted. Control trials 2–60
  are unconditional and do not require valid preceding neurofeedback.
- `clean_feedback_rt_pairs`, `summarize_feedback_rt_quality`: sequential
  incorrect, timeout, invalid RT, <150 ms, and one-pass ±3 sample-SD exclusions.
  SD strata are participant × session × current type, pooled across runs and
  previous feedback. Empty/singleton/zero-SD strata are reported. Subject loss
  >50% excludes the participant; exactly 50% does not. Technical losses stay
  outside the behavioral/RT exclusion denominator.
- `summarize_feedback_rt`: pool trials within participants first, including
  trial-weighted pooling across current types for overall RT. Group means,
  SD/SEM and t-distribution 95% CIs use participant means; missing cells stay NaN.
- `run_feedback_rt_statistics`, `feedback_sphericity`: statsmodels `AnovaRM`
  with model-specific complete cells for overall feedback, feedback × current
  type, and each current type separately. There are no session/run/group
  factors. Mauchly W and GG epsilon use orthonormal feedback contrasts; the
  3×2 interaction uses three current-type difference scores. The specialized
  three-level sphericity implementation is checked against the published
  [Pingouin example](https://pingouin-stats.org/generated/pingouin.sphericity.html).
  Apply GG when Mauchly p<.05; report raw/GG and selected df/p separately.
  Pairwise-complete paired t-tests use first-minus-second differences, unadjusted
  difference CIs, Cohen's dz, and Holm within each family of three contrasts.
- `validate_feedback_rt_results`: independent contrast-based F calculations,
  Holm calculations, and count conservation checks.
- `plot_feedback_next_trial_rt`, `save_feedback_rt_tables`: participant points,
  mean±SEM, unconditional control lines, shared scales, vector PDF and PNG;
  validated requested CSV exports. Arial follows this analysis's explicit request.
