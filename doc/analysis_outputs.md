## When to use this file
Use this file when:
- locating generated CSV files in the `analyses` folder
- understanding the row grain and columns of consolidated analysis tables
- deciding which CSV to use for downstream statistics or plotting

Do NOT use this file for:
- locating raw data files (see `file_structure.md`)
- interpreting raw text or `.mat` file contents (see `file_contents.md`)
- understanding experimental run counts and subject-specific exceptions (see `experiment_structure.md`)

## Common Metadata Columns

The consolidated CSVs follow the same basic organization:

- `subject_id`
  - Subject identifier, e.g. `e21`.
- `group`
  - Group assignment from `code/src/posthoc_analysis/config.py`.
  - Values:
    - `experimental` = BCI group
    - `control` = mental-rehearsal control group
- `session_id`
  - Integer session number in experiment order.
  - Values usually range from `1` to `5`.
- `run_id`
  - Sequential non-practice run number within that subject/session after consolidation-specific practice handling.
  - For documented exceptions, see `experiment_structure.md`.

## `all_subjects_training.csv`

### Purpose
Trial-level consolidated training-task data across subjects, Sessions 1 and 5, and non-practice training runs.

### Generated by
`posthoc_analysis.consolidated.generate_consolidated_training_csv()`

### Row grain
One row = one training trial.

### Current expected shape
- 11,460 rows × 15 columns

### Columns

- `subject_id`
  - Subject identifier.
- `group`
  - `experimental` or `control`.
- `session_id`
  - Training session number.
  - Training is expected in Sessions `1` and `5`.
- `run_id`
  - Sequential training run number within session after excluding `training_practice`.
  - Session 1 typically has runs `1` to `8`.
  - Session 5 typically has runs `1` to `4`.
- `task_type`
  - Run task label parsed from the run folder name.
  - Expected value for this CSV: `training`.
- `trial`
  - Trial index within run.
  - Expected values: `1` to `60`.
- `task`
  - Trial type from `.analysis.txt`.
  - `1` = distractor
  - `0` = no distractor
- `feedback`
  - Behavioral response outcome.
  - `1` = correct
  - `2` = incorrect
  - `3` = timeout
- `target_position`
  - Target location code from `.analysis.txt`.
  - Expected values: `1`, `2`, `3`, `4`.
- `distractor_position`
  - Distractor location code from `.analysis.txt`.
  - Expected values: `0`, `2`, `4`.
  - `0` indicates no distractor.
- `dot_side`
  - Response side.
  - `1` = right
  - `0` = left
- `intertrial_interval_ms`
  - Intertrial interval in milliseconds.
- `bci_output`
  - BCI output column from `.analysis.txt`.
  - For training runs, expected value is `99`.
- `rt_samples`
  - Reaction time computed from trigger timing in samples.
  - Computed as response trigger time minus stimulus trigger time.
- `rt_ms`
  - Reaction time converted to milliseconds using 512 Hz sampling.

## `training_session_condition_eeg_averages.csv`

### Purpose
Session-level EEG waveform averages for training data, split by stimulus
condition and generated using the canonical Pd preprocessing chain.

### Generated by
`posthoc_analysis.eeg.generate_session_condition_eeg_averages_csv()`

### Row grain
One row = one subject × session × condition × time sample.

Channel columns store the session-level average EEG matrix. For each
subject × session × condition, the matrix is:

- **768 samples × 61 analysis EEG channels**

### Averaging rule
The function first computes run-level condition averages, then averages those
run-level matrices within session. This keeps condition labels and run structure
explicit and avoids pooling trials across runs before run-level averaging.

### Preprocessing
- Exclude non-analysis channels: `M1`, `M2`, `EOG`, `sens7`, `sens8`
- Zero-phase bandpass filter: `0.1-20 Hz`
- Stimulus-locked epochs: `-0.5` to `1.0` s relative to triggers `8`, `32`, `44`
- Baseline correction: `-0.2` to `0` s, sample indices `154:256`

### Current expected shape
- 147,456 rows × 69 columns

This is:

`32 subjects × 2 sessions × 3 conditions × 768 samples`

### Columns

- `subject_id`
- `group`
- `session_id`
- `condition`
  - `distractor_left`
  - `distractor_right`
  - `no_distractor`
- `sample_index`
- `time_sec`
- `n_runs`
- `expected_n_runs`
- one column per analysis EEG channel, 61 total

### Companion manifest
`training_session_condition_eeg_averages_manifest.csv`

One row = one subject × session × condition. Includes:

- `n_runs`
- `expected_n_runs`
- `matrix_shape`
- `run_condition_counts`
- `run_status_counts`

### Current data-quality notes
- `e30` Session 1 has 7 available non-practice training runs instead of the
  expected 8. The CSV includes the session average across the 7 available
  run-level averages and records `n_runs=7`, `expected_n_runs=8`.
- Some runs have fewer than 60 response Status events (`64`), but all 60
  stimulus Status anchors are present and valid. Because this output is
  stimulus-locked, those runs are retained and the response-event counts are
  preserved in the manifest.

### Pd plotting from this CSV
`posthoc_analysis.eeg.load_and_plot_group_pd_pre_post_from_condition_csv()`
loads this CSV and computes subject/session Pd from condition-average matrices:

- `distractor_right`: `PO7 - PO8`
- `distractor_left`: `PO8 - PO7`
- `no_distractor`: validated but ignored for Pd

The group plots compare Session 1 vs Session 5 separately for the BCI and
mental-rehearsal control groups. Lines are subject-averaged Pd waveforms, shaded
bands are SEM across subjects, the displayed time range is `-0.2` to `0.7` s,
and the `0.2` to `0.5` s decoder construction window is shaded.

Default saved figure names:

- `figures/training_pd_bci_pre_post.pdf`
- `figures/training_pd_control_pre_post.pdf`

## `training_pd_positive_auc_0p2_0p5.csv`

### Purpose
Subject/session Pd positive area under the curve within the decoder
construction window.

### Generated by
`posthoc_analysis.eeg.load_compute_and_run_pd_positive_auc_anova()`

### Row grain
One row = one subject × session.

### Computation
The function first computes subject/session Pd from
`training_session_condition_eeg_averages.csv` using the documented PO7/PO8
contralateral convention. Positive AUC is then computed from `0.2` to `0.5` s
as the trapezoidal integral of `max(Pd, 0)`.

### Columns

- `subject_id`
- `group`
- `session_id`
- `time_window_start_sec`
- `time_window_end_sec`
- `n_samples`
- `positive_auc_uv_sec`
- `mean_pd_uv_in_window`
- `mean_positive_pd_uv_in_window`

### Statistical use
The corresponding ANOVA helper runs a 2 × 2 mixed-design ANOVA:

- between-subject factor: `group` (`bci`, `control`)
- within-subject factor: `session_id` (`1`, `5`)
- dependent variable: `positive_auc_uv_sec`

The same helper also reports planned contrasts:

- within BCI group: Session 5 minus Session 1
- within mental-rehearsal control group: Session 5 minus Session 1
- between groups at Session 1: BCI minus control
- between groups at Session 5: BCI minus control

Uses the same RT cleaning convention as the primary training RT analysis:

- training rows only

## Color/Shape Planned Correct-Trial RT Pipeline

### Purpose
Final Color/Shape RT cleaning pipeline for downstream RT analyses.

### Generated by
`posthoc_analysis.color_shape.load_clean_and_plot_color_shape_planned_rt_pipeline()`

### Cleaning Order

1. Start from `all_subjects_color_shape_main_task_annotated.csv`.
2. Keep correct response trials only (`chose_best == 1`).
3. Remove correct trials with `rt < 150 ms`.
4. Within each subject/session, compute median RT and MAD from the remaining
   correct trials.
5. Remove trials where `abs(rt - median_rt) > 3 * MAD`.
6. Compute subject/session mean RT from retained trials.

### Current Cleaning Summary

- Starting main-task trials: 19,200
- Incorrect-response trials removed before RT analyses: 1,614
- Correct trials removed for `rt < 150 ms`: 3
- Correct trials removed as 3 MAD RT outliers: 2,206
- Total trials removed across all steps: 3,823
- Trials retained for RT analyses: 15,377

## Color/Shape Mixed ANOVAs

### Purpose
Mixed ANOVAs for #21 accuracy and #22 RT, run separately for congruent and
incongruent trials.

### Generated by
`posthoc_analysis.color_shape.load_and_run_color_shape_mixed_anovas()`

### Source
`color_shape_summary_long.csv`

### Design

- between-subject factor: `group` (`bci`, `control`)
- within-subject factor: `session` (`pre`, `post`)
- subject identifier: `subject_id`

### Implementation note
The implementation uses `pingouin.mixed_anova` when `pingouin` is installed.
In the current environment, `pingouin` is not installed, so the saved tables use
the equivalent tests for this 2-group × 2-session design:

- group effect: independent t-test on each subject's pre/post mean
- session effect: one-sample t-test on each subject's post-pre change score
- group × session interaction: independent t-test on post-pre change scores by
  group

The fallback reports `F = t²`, matching the 1 df effect tests for this design.
